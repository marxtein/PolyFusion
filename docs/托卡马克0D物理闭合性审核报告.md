# 托卡马克 0D 物理闭合性审核报告

日期：2026-06-10  
对象：`polyfusion/tokamak.py`、`polyfusion/presets.py`、`polyfusion/configs/base.py`、`polyfusion/scan.py`，对照 `docs/01_托卡马克代码说明文档.md`、`docs/19_托卡马克模块验证.md`  
结论级别：物理审稿式问题清单；本报告不修改源码

## 1. 总结结论

托卡马克模块是当前 release 中最成熟、最接近传统 0D 系统程序的位形。它的主线非常清楚：

```text
几何/剖面/组分
  -> 反应率积分 Phi
  -> Pfus / Pbrem / Pcycl
  -> Eth / Pth = Eth/tauE
  -> Pheat = losses - alpha heating
  -> Qfus
  -> betaN / betaT / betap / q / Greenwald / H98 / HST 后验诊断
```

已有文档和测试给它提供了较强支撑：

- D-T 反应率与 Bosch-Hale 拟合在 5-100 keV 范围内最差误差约 0.6%。
- ITER IPB98y2 约束时间 benchmark：代码约 3.62 s，对照文献约 3.66 s。
- ITER Greenwald 密度极限 benchmark：约 `1.19e20 m^-3`，对照闭式结果一致。
- ITER 预设给 `Pfus≈381 MW`、`Q≈5.03`，与 ETSC 原始 JS/golden 结果一致。

因此，托卡马克模块可以作为：

> 托卡马克 0D 功率平衡、POPCON 教学、参数初筛和与其他位形对照的基准模块。

但它仍不是完整 tokamak reactor design code。最大边界是：

> `tauE` 是输入，不是预测；IPB98/H98 只是后验品质因子。

此外，电流驱动、alpha 自洽、台基/ELM、破裂、垂直稳定、divertor、杂质线辐射、中子屏蔽、磁体工程都不在模型里。当前还有明显的输入域保护缺口：非法组分、`Rw>1`、负剖面指数、负壁间隙、极端 Ip 都会给出假结果或复数结果。

## 2. 已经闭合的部分

### 2.1 聚变反应率和功率链条

代码使用 `reactivity(T, icase)`，并对径向剖面做加权积分：

```text
Phi = fsig * 2 * ∫ (1 - x^2)^(2Sn) <sigma v>(T_i0(1-x^2)^ST) x dx
Pfus = Y/(1+delta12) * n10 * n20 * Phi * Vp
```

`test_literature_benchmark.py` 已验证：

```text
D-T <sigma v>(10 keV) = 1.136e-22 m^3/s
Bosch-Hale anchor = 1.13e-22 m^3/s
5-100 keV 最差相对误差约 0.6%
```

这说明聚变反应率内核是可信的，也是其他位形复用它的基础。

### 2.2 主功率账闭合

ITER 预设复算：

| 量 | 数值 |
|---|---:|
| `Pfus` | 381.391 MW |
| `Pn` | 305.113 MW |
| 带电聚变功率 | 76.278 MW |
| `Pth` | 136.208 MW |
| `Pbrem` | 9.744 MW |
| `Pcycl` | 6.099 MW |
| `Pheat` | 75.772 MW |
| `Qfus` | 5.033 |

功率账：

```text
Pheat = Pth + Pbrem + Pcycl - fion Pfus
      = 136.208 + 9.744 + 6.099 - 76.278
      = 75.772 MW
```

内部账本是闭合的。

### 2.3 后验约束指标合理

ITER 预设输出：

| 指标 | 数值 | 解读 |
---|---:|---|
| `H98` | 1.495 | 需要比 IPB98y2 数据库均值高约 50% 的约束假设 |
| `betaN` | 2.27 | 在常见 Troyon 无壁极限量级内 |
| `betaT` | 2.18% | 反应堆尺度合理 |
| `nbar/nGw` | 0.707 | 低于 Greenwald |
| `q` | 2.83 | 大于常见 kink 安全边界 |
| `Pwall` | 0.653 MW/m^2 | 反应堆尺度中子/壁负载量级 |

这说明 ITER 预设确实像一个传统燃烧等离子体 0D 点，而不是随便拼出来的数。

### 3.3 边界测试暴露的问题

#### P0：非法组分仍给结果

测试：

```python
run_case({"fHe": 0.7, "fimp": 0.4}, preset="ITER", config="tokamak")
```

输出摘要：

```text
Zeff = 8.0566
Pfus = 4.226 MW
Pheat = 1302.50 MW
nbar/nGw = 3.318
```

此时 `f12 = 1 - fHe - fimp = -0.1`，燃料密度为负。代码仍给出结果，说明组分校验缺失是全位形共性 P0 问题。

#### P0：`Rw > 1` 产生复数功率和复数 H

测试：

```python
run_case({"Rw": 1.2}, preset="ITER", config="tokamak")
```

输出摘要：

```text
Pheat = 69.67 + 4.98 i
Qfus = 5.45 - 0.39 i
H98 = 1.45 + 0.034 i
```

物理上壁反射率必须满足 `0 <= Rw <= 1`。复数功率不应进入输出。

#### P0：负剖面指数崩溃

测试：

```python
run_case({"Sn": -1}, preset="ITER", config="tokamak")
```

结果：

```text
ZeroDivisionError: float division by zero
```

当前剖面族 `(1-x^2)^S` 在 `S<0` 时边界可能发散，而且代码中的解析分母会归零。对当前教学模型，应限制：

```text
Sn >= 0
ST >= 0
```

#### P0：负壁间隙会产生负壁面积

测试：

```python
run_case({"g": -2}, preset="ITER", config="tokamak")
```

输出仍为 OK，但：

```text
Sw = -55.88 m^2
```

壁面积为负没有物理意义。应要求：

```text
g >= 0
Ad = R0/(a+g) 有效
Sw > 0
```

#### P1：极端低电流仍给出离谱后验

测试：

```python
run_case({"Ip": 0.01}, preset="ITER", config="tokamak")
```

输出：

```text
H98 = 852.95
nbar/nGw = 650.77
q = 2600.15
```

best-window 会排除 `nbar/nGw > 1`，但单点仍显示完整结果。对用户来说，这类点应明确标记为“后验红线严重违反”，否则容易误读。

#### P1：`Qfus=1000` 混淆点火、负加热和数值截断

在 ITER 小扫描中，高密度高温点出现：

```text
Pheat < 0
Qfus = 1000
```

当前逻辑：

```python
Qfus = Pfus / Pheat if Pheat > 0 else 1000.0
if Qfus <= 0 or Qfus > 1000: Qfus = 1000.0
```

这会把三种不同状态混在一起：

- 接近点火，外部加热趋近 0。
- 公式给出负外部加热，表示 alpha heating 超过损失。
- 数值/输入异常导致的非物理结果。

建议输出额外状态：

```text
ignited = Pheat <= 0 and all constraints valid
Q_display = capped value
Q_raw = Pfus/Pheat when Pheat != 0
```

## 4. 关键物理缺口

### 4.1 `tauE` 是输入，不是预测

托卡马克模块计算：

```text
Pth = Eth / tauE
H98 = tauE / tauE_IPB98
```

所以 H98 是“你输入的 `tauE` 比 IPB98y2 数据库回归好多少”，不是代码自己预测了约束。任何高 Q 点都必须同时看 H98/HST。

例如 p-B11 概念点 `H98 = 10-15`，意味着需要远超常规数据库的约束假设。不能只看 Q。

### 4.2 MHD 与运行极限只是后验

代码输出 `betaN`、`q`、`nbar/nGw`，但它们不进入主功率方程。真实 tokamak 可行性还依赖：

- betaN/Troyon/no-wall/resistive-wall limit。
- q95、sawtooth、NTM、kink、vertical stability。
- Greenwald/density limit。
- pedestal、ELM、L-H mode。
- disruption risk。

当前 POPCON best-window 只用一部分后验指标，不能代表完整运行边界。

### 4.3 辐射和杂质模型很粗

当前 `Pbrem` 是连续轫致表达式，并有简单相对论修正；没有：

- 线辐射。
- 多杂质种类。
- 辐射分布和 divertor detachment。
- 灰分积累和氦排灰。

对高 Z 杂质、p-B11 高温电子、强辐射工况，当前辐射模型可能明显低估或误估损失。

### 4.4 工程系统完全缺失

0D 功率账没有：

- 电流驱动功率和效率。
- NBI/RF 加热沉积。
- 磁体应力、超导裕度。
- 中子屏蔽、氚增殖、热工循环。
- Divertor 热流。
- 成本和可维护性。

这些不应强加给一个 0D 教学模型，但必须在报告/UI 中诚实标注。

## 5. 文献对照

可作为审核依据的高可信来源：

- ITER Physics Basis / IPB98(y,2) confinement scaling, Nuclear Fusion 39 (1999).  
  用于核对 IPB98y2 的形式和 ITER 约束时间量级。
- Greenwald et al., "A new look at density limits in tokamaks", Nuclear Fusion 28 (1988). DOI: https://doi.org/10.1088/0029-5515/28/12/009  
  用于核对 Greenwald density limit。
- Troyon et al., normalized beta limit, Plasma Physics and Controlled Fusion 26 (1984).  
  用于核对 `betaN` 作为后验 MHD 限制。
- Bosch & Hale, "Improved formulas for fusion cross-sections and thermal reactivities", Nuclear Fusion 32 (1992). DOI: https://doi.org/10.1088/0029-5515/32/4/I07  
  用于核对 D-T/D-D/D-He3 反应率。
- `docs/19_托卡马克模块验证.md`  
  已记录 Bosch-Hale、IPB98y2、Greenwald benchmark。

对照结论：托卡马克模块有最强的文献验证基础；它适合做 0D POPCON 和多位形基准。但仍应严格区分“系统程序后验诊断”和“完整 reactor design”。

## 6. 修正优先级

### P0：输入域和非实数保护

- 校验 `R0 > 0`、`A > 0`、`kappa > 0`、`BT0 > 0`、`Ip > 0`、`tauE > 0`。
- 校验 `g >= 0` 且 `Sw > 0`。
- 校验 `Sn >= 0`、`ST >= 0`、`fT > 0`。
- 校验 `0 <= f1 <= 1`、`0 <= fHe`、`0 <= fimp`、`fHe + fimp <= 1`、`Zimp > 0`。
- 校验 `0 <= Rw <= 1`。
- 禁止复数、NaN、inf 的 `Pheat/Q/H98/Pcycl/Pbrem` 进入有效输出。

### P1：区分点火、截断和非法点

建议新增：

```text
Pheat_raw
Qfus_raw
Qfus_capped
ignited_flag
valid_physics_flag
```

UI 中 `Q=1000` 应显示为“点火/自持候选”或“截断”，而不是普通等值线。

### P1：把后验红线更明确地暴露给 POPCON

建议 best-window 至少包含：

```text
nbar/nGw <= 1
betaN <= 3 或用户阈值
q >= 2
H98 <= 用户阈值
```

p-B11 概念点可允许用户放宽，但必须显式显示激进程度。

### P2：若要升级到反应堆设计工具

需要：

- 电流驱动和 bootstrap current。
- Pedestal/ELM/L-H mode。
- Divertor heat flux 和 detachment。
- 杂质线辐射和灰分。
- Alpha heating/fast ion orbit。
- MHD stability database 或 equilibrium solver。
- 工程系统和热工循环。

## 7. 推荐对外表述

建议将托卡马克模块描述为：

> 托卡马克模块是基于 0D 功率平衡、热反应率积分、经验辐射、输入 `tauE` 和 IPB98/Greenwald/Troyon 后验诊断的 POPCON 系统程序。它适合教学、扫参和与 ITER/SPARC/CFETR 等量级对照；不包含电流驱动、台基/ELM、破裂、divertor、杂质线辐射、alpha 轨道和工程系统，因此不能单独用于执照级或工程级反应堆预测。

## 9. 最终判断

托卡马克模块是多位形系统里的基准模块。它的反应率、IPB98、Greenwald 等关键文献锚点已经通过验证，功率账也闭合。作为 0D POPCON 教学/扫参工具，它是可信的。

但它仍然只是 0D scoping model。必须补输入域保护，尤其是组分、剖面、反射率、壁间隙和非有限输出；同时必须把 `Q=1000` 从“普通高增益”中区分出来。对概念 p-B11 点，要把 H98、betaN、betaT 的激进程度放在和 Q 同等显眼的位置。

## 10. 物理可靠性再审：能不能用于装置设计？

托卡马克是当前多位形里最可靠的基准模块，但这句话有边界：

```text
D-T 热等离子体 0D POPCON：可信度最高；
托卡马克系统工程设计：还不够；
p-B11/先进燃料托卡马克：当前模型可信度低。
```

### 10.1 可靠的部分

- 反应率、聚变功率、轫致辐射、热能账本、Greenwald、IPB98、betaN/q 等输出，属于托卡马克 0D 系统程序的标准骨架。
- `H98 = tauE/tauE98` 的解释是正确的：它能告诉用户“这个点需要多强的约束品质”，这比只看 Q 可靠得多。
- 对 ITER/SPARC/CFETR 这类 D-T 点做量级对照，是当前代码最有物理支撑的用法。

### 10.2 不可靠的设计环节

第一，`tauE` 是输入，不是由模型自洽求出。当前代码不是“预测 tauE 后算 Q”，而是“用户给 tauE 后算功率账，再输出 H98”。因此 POPCON 高 Q 区域必须同时看 H98 是否可实现。

第二，当前没有自洽求解 L-H 阈值、pedestal、H-mode/ELM、disruption、current drive、bootstrap current、燃料循环、helium ash、杂质线辐射、辐射分布、divertor 热负荷和核热工程。真实托卡马克设计常常不是 core Q 卡住，而是边界/电流/材料/稳态功率处理卡住。

第三，`Q=1000` 截断会掩盖不同物理状态。真实点火、alpha 自热超过损失、负外部加热、非法输入导致的负功率，都可能被压成同一个数字。这对设计工具很危险。

第四，先进燃料尤其 p-B11 不能直接沿用 D-T 热等离子体直觉。p-B11 需要更高温度，轫致和回旋辐射压力更大，常见方案依赖非热分布、直接能量转换或特殊辐射回收。当前热麦克斯韦 0D 只能做“惩罚性初筛”，不能证明 p-B11 托卡马克可行。

### 10.3 设计使用等级

| 用途 | 当前可信度 | 说明 |
|---|---:|---|
| D-T 0D 教学和 POPCON 初筛 | 高 | 文献锚点强 |
| ITER/SPARC/CFETR 量级对照 | 中-高 | 需同时看 H98、betaN、q、Greenwald |
| 稳态电站系统设计 | 中-低 | 缺 current drive、divertor、ash、工程闭合 |
| p-B11/先进燃料可行性判断 | 低 | 缺非热、辐射、直接能量转换 |
| 工程级 reactor design | 不足 | 需要系统代码和边界/材料/核工程链 |

### 10.4 更可靠的托卡马克方案

建议把托卡马克从“给定 tauE 算 Q”升级为“目标 H 因子和约束红线共同求解”的系统前端：

1. 把 `tauE` 和 `H98_target` 都作为可选输入。若给 `H98_target`，程序应隐式求解 `tauE = H98_target * tauE98(P_loss)`，而不是让用户手填一个可能不物理的 `tauE`。
2. 把 `Qfus` 拆成 `Q_raw`、`Q_capped`、`ignited_flag`、`invalid_flag`，避免点火和非法负功率混在一起。
3. POPCON best region 必须同时满足：`H98` 可接受、`betaN` 可接受、`q95/q` 可接受、`nbar/nGw` 有裕度、`Pwall` 有裕度、`Pheat` 状态明确、输入域有效。
4. 加边界和工程近似：L-H 阈值、辐射分数、divertor heat flux proxy、current drive power、bootstrap fraction、helium ash、Zeff/杂质线辐射。

最低可接受升级：

```text
托卡马克设计判断 = core 0D 功率账
                 + H98 目标/约束自洽
                 + betaN/q/Greenwald/Pwall 红线
                 + 点火状态分类
                 + divertor/current-drive/ash 的一阶工程 proxy
```

对 p-B11，建议单独建 “advanced-fuel warning mode”：默认不把高 Q 当作可行，必须同时输出轫致占比、回旋占比、所需温度、所需 beta、所需 H98、直接能量转换假设和非热分布假设。
