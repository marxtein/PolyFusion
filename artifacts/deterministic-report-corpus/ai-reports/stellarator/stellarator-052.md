# 1. 核心结论

当前运行点与扫描结论需要分开看：

- 运行点：`config=stellarator`（`config_label=仿星器 Stellarator`），`preset=HELIAS`，`valid=1.0`，`ignited=0.0`，`Pfus=4496.151206661675`，`Qfus=8.440282752131251`，`Pheat=532.7014910165603`，`Pwall=3.155867131588128`。
- 这表示该单个 0-D 运行点求解有效，但没有显示为点火；`valid=1.0` 不能等同于“POPCON 已确认存在工作窗”。
- POPCON 扫描：`xkey=Ti0`，`ykey=ni0`，`n_invalid=0`，且 `best` 矩阵存在非零项，说明在当前判据下至少有部分网格点被标记为 `best`。
- 但本次 `last_scan` 未提供 `x/y` 数组，也未给出 `nx/ny`。因此：**扫描网格证据不足，不能判断工作窗形状或敏感性趋势**。

# 2. 关键指标解读

- 约束时间：`use_tauE=1.0`，`tauE_used=1.0`，说明**结果依赖固定约束时间假设**。同时输出了 `tau_ISS04=0.5711230143982958` 和 `H_ISS04=1.7509362690515031`，可作为与 ISS04 标度的对照。

- 旋转变换：`iota=0.8220570026198248`。`q/q95`、`betaN`、`betap` 等字段未提供，因此这些边界不能展开判断。

# 3. 风险与不确定性

- 最主要的不确定性来自 `use_tauE=1.0`：本次结果不是由约束标度自洽求出的 `tauE` 主导，而是依赖固定 `tauE=1.0` 假设。
- `geom_model` 字段未提供，无法按该字段判断几何模型简化级别；但 `geom_is_measured=0.0` 表明这里不是“实测几何回填”场景。
- POPCON 侧虽然 `best` 矩阵有非零项、`n_invalid=0`，但缺少 `x/y` 数组与 `nx/ny`，所以不能判断最佳区位置、边界、连通性，也不能判断对 `Ti0` 或 `ni0` 的敏感性趋势。
- `ignited=0.0` 说明当前运行点不能直接表述为点火态；同时单点 `valid=1.0` 也不代表扫描上存在连续、宽容的可操作区域。
