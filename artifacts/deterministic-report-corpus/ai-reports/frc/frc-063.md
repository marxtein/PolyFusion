# 1. 核心结论

本次 0-D 结果对应 `config=frc`、`preset=C-2W`。当前运行点 `valid=1.0`，说明该点在模型判定下是可计算/有效的；但 `ignited=0.0`，未显示点火。该点输出为：`Pfus=1341.0759`、`Qfus=0.03128`、`Pheat=42872.8767`、`Pwall=3257.8098`。

需要把“单点运行”和“POPCON 扫描”分开看：
- 当前运行点有效，只说明这一个参数点通过了模型内的有效性检查。
- POPCON 扫描是否找到满足准则的区域，要看扫描结果本身，不能用 `valid=1` 代替。

本次扫描给出了 `best` 矩阵，且其中至少有一个 `1`，因此不能写“当前准则下未找到最佳区”。但由于 JSON 未提供 `x`/`y` 扫描数组，也未提供 `nx`/`ny`，**扫描网格证据不足，不能判断工作窗形状或敏感性趋势**。

此外，`use_tauE=1.0`，说明结果**依赖固定约束时间假设**；这会直接影响对 `Qfus`、功率平衡和扫描结论的解读。

# 3. 风险与不确定性

- 最大的不确定性来自 `use_tauE=1.0`。由于 `tau_E` 被固定为 `0.0015`，当前 `Pfus`、`Qfus`、`ignited` 以及扫描结果都依赖这个约束时间假设。
- 扫描证据不完整。虽然有 `best` 矩阵，但缺少 `x`/`y` 数组和网格尺寸信息，**扫描网格证据不足，不能判断工作窗形状或敏感性趋势**。
- `valid=1.0` 不等于“扫描找到了可用工作窗”。它只说明当前单点在模型里有效，不能替代二维扫描判读。
- `ignited=0.0` 说明该运行点没有显示点火；不能把存在 `best` 格点理解为已经达到点火。
- 辐射项中 `P_line=0.0` 与 `fimp=0.0` 的输入设定强相关，因此对杂质敏感性的信息很有限。
- JSON 中未提供 `H98`、`H_ITPA20`、`H_ISS04`、`q95`、`betaN`、`nbar_o_nGw` 等字段，相关约束无法展开判断。
- 几何字段里没有 `geom_model`，因此不能对“几何模型是否较简化”做指定结论。
